# Parity evidence and intentional differences

Reference: Thomas Unise's CaseCite commit
`6605cb3474cf0c2894080af216d5fed2a81fc997`. The implementation is in progress;
this document is not a declaration of complete parity.

## What “cross-checking” means

For each feature, inspect its Python route, schemas, services, tests, and the
actual React or Word consumer. Check authorization, accepted input, returned
fields, persistent state, asynchronous execution, errors, and exports. Matching
an endpoint name or screenshot does not establish functional equivalence.

Preserve intended functionality. Do not reproduce a known upstream defect just
to make an implementation identical. Record the difference, its reason, and a
regression test. Nondeterministic model quality and real provider integrations
need separate evaluation; a mocked provider cannot prove those properties.

## Intentional improvements

- OCR uses GoodMem's on-premise API and keeps completed pages across retries.
  Image-bearing pages are not treated as fully read merely because a heading
  is searchable. Missing/failed pages block full-document analysis. Source
  previews show OCR provenance and page numbers. A failed OCR index can be
  retried without uploading the original again. This intentionally replaces
  upstream's fallback to whatever native text happened to survive.
- Real GoodMem ingestion of an image-only PDF exposed a separate gap: the
  pinned image's normal ingestion path does not invoke its OCR API. The Go
  upload path now queues OCR and creates a searchable text memory in GoodMem,
  preserving original bytes/page images and original-document citations. Both
  memories are removed on deletion, with durable cleanup for late remote writes.
- Judge searches use documented author/panel IDs and full names instead of
  a surname-only OR query. Per-judge writing metrics exclude other authors'
  dissents and text. Citation relationships use individual opinion IDs, fixing
  upstream's cluster-ID mismatch. Docket searches use docket results, deduplicate
  IDs and enforce the requested limit. The field contracts were checked against
  [CourtListener's search documentation](https://wiki.free.law/c/courtlistener/help/search/advanced-search-and-query-techniques).
- Judge case-duration medians average both middle values for even samples.
  Bench tenure excludes identified non-judicial jobs, merges overlapping years
  and picks the latest active position. Zero observations are insufficient data;
  profile completeness does not establish statistical confidence. Summary text
  avoids uncomputed peer averages and claims about judicial efficiency.
- Judge builds and cache publication share the job transaction. Duplicate builds
  do not consume extra queue slots; refresh keeps the last complete profile;
  cancellation, deletion and lease failure cannot publish a late replacement.
  Concurrent opinion reads merge their cache changes instead of losing text.
  Read-only profile requests use the cached snapshot; explicit rebuild refreshes
  missing dockets instead of triggering repeated hidden provider calls on GET.
- Wikipedia namesake checks retain the original name/profession/birth-year
  safeguards and handle name suffixes. Full text counts reflect stored text,
  failed primary datasets fail the build, and optional-data failures are visible.
  Metadata fields and all nine actual metrics remain available; the unused
  political-alignment methodology entry is omitted.
- An explicit opinion/cluster kind now stays in that namespace. Upstream falls
  back after a 404, which can display an unrelated case with the same number.
  Bare IDs retain cluster-first lookup. Upstream server errors no longer become
  false "case not found" responses or trigger the wrong namespace lookup.
- CourtListener credentials are sent only to the configured API origin;
  provider references are resolved as typed IDs and cursors must target the
  search endpoint. External court download links remain available to users.
- The shared request gate rechecks new retry penalties for callers already
  waiting, and supports HTTP-date `Retry-After`. Trends use one bounded retry
  layer instead of multiplying the service and transport retries. Failed
  credentials produce an error rather than an apparently empty trend chart.
- Trend direction excludes future years as well as the partial current year;
  invalid reversed year ranges are rejected. Complete results and court names
  use expiring PostgreSQL records, including per-user credential separation for
  trend queries, so restart and multiple-instance behavior need no Redis.
  The chart marks the actual current year and describes failed counts without
  claiming they must be rate-limit failures.
- Citation checks recognize multi-part reporters such as `S. Ct.` and
  `F. Supp. 3d`, retain numeric citing IDs and normalized filing dates, and
  strip highlight tags from case names. Complete response fixtures retain the
  original explanatory notes and closest-result guidance for unmatched cases.
- The main case reader now displays available concurrences and dissents, which
  upstream's main view omits despite receiving them. Precedent links explicitly
  identify cluster IDs, pagination clears exhausted cursors, and icon-only
  legal search buttons have accessible names. Phone search controls clear the
  floating navigation/source buttons; they previously overlapped them.
- Standalone research creates its run and job in one transaction. The original
  saves the run before queue submission, allowing failed admission to leave a
  stranded run. Deleting an active run now cancels the associated job, and
  cancellation/lease failure update run history transactionally.
- Research rechecks every retrieved document after synthesis before publishing
  its result; access revoked during generation cannot publish retrieved content.
- Explicit empty document filters do not become all-readable searches. Planner
  caps below three no longer produce contradictory instructions such as “3–1”.
- The original research source UI interprets `warning_level=unknown` as treatment
  found, even when zero citing opinions were read. It now displays “Treatment
  undetermined”; unit tests cover failed, uncertain, clean and flagged scans.
  The planning panel describes CourtListener as available without implying
  that a documents-only plan will contact it.
- Upstream workflow continuation can mutate run state before model-key and
  queue checks succeed. The Go decision/reset and job enqueue share one
  transaction; failed preflight leaves the approval/run untouched. Concurrent
  approval tests prove that only one continuation is created.
- Upstream resume treats an explicitly skipped step like an unfinished step
  and can rerun it after a later failure. Explicit skip decisions are retained;
  retry remains available when a user deliberately wants to rerun that step.
- An empty workflow research input is kept empty. The upstream adapter turns
  it into an unrestricted scope, which can search documents the user did not
  select. Zero-document scope has a regression test proving no retrieval call.
- Research quote verification requires the entire quote to match its passage.
  The original fallback verifies a quote's longest matching sentence but marks
  the whole quote verified, including potentially invented adjacent sentences.
  A regression checks a real sentence followed by a fabricated sentence.
- Citation matching rejects different reporter pages that share a substring,
  while accepting pinpoint citations and year parentheticals. Failed citing
  listings cannot produce a clean treatment conclusion. Citation queries use
  opinion IDs, not cluster IDs. HTTP contact reporting includes failed requests.
- Workflow email events capture the approval gate at transition time, avoiding
  the original notification helper's use of the last approval title in a run.
  HTML is escaped and users who lost access are excluded before queuing mail.
- Workflow output byte limits include truncation metadata. Non-finite numeric
  conditions are rejected. Approval/citation-only runs do not require a model
  key. Duplicate workflows validate named approvers against the new scope.
- Workflow phone controls wrap without squeezing the title or decision input;
  output panels have named groups and expanded-state accessibility attributes.
- Upstream review-table result writes do not recheck current table scope and
  can recreate a removed row/column or race with a reviewer's changes. Parent
  row locks, fresh scope/permission checks and active job leases protect every
  document write. A concurrent second run gets an explicit conflict response,
  preventing competing runs from overwriting each other or duplicating cost.
- Upstream numeric `0` and boolean `false` model values are treated as absent
  by a truthiness check. The Go extractor preserves zero and converts boolean
  answers to the requested yes/no representation, with regression tests.
- Review-table exports explicitly encode XLSX strings and protect formula-like
  CSV values. Source quotes, model values, notes and filenames cannot become
  executable spreadsheet formulas. Tests inspect the OOXML independently and
  check internal citation hyperlinks, overrides and summary counts.
- The original review schema editor nests a template-save form inside the
  create-review form. Saving a template can submit both forms. The embedded
  editor uses a separate button action and a scoped Enter handler. Regression
  tests verify both keyboard and mouse behavior without creating a review.
- The original review toolbar can squeeze the title to zero width on phones.
  It now wraps, with the source panel stacked below the grid and export options
  kept inside the viewport. Desktop and phone browser checks exercise these
  controls; this is not evidence for other screens' mobile parity.
- The original contract Q&A drops ungrounded quotes without updating inline
  citation numbers. If quote 1 is discarded, an answer's `[2]` no longer points
  to its source. The Go version remaps retained citations and visibly labels
  unsupported references. Unit and API tests cover a discarded first quote.
- DOCX redlines patch the original package and affected runs. The original
  Python exporter rebuilds a document from plain text and explicitly does not
  carry run formatting. The Go exporter preserves unrelated ZIP members,
  paragraph/run formatting, tables, headers, relationships and images.
- A repeated quote with a stale offset is reported as unapplied instead of
  choosing an occurrence arbitrarily. A matching stored offset still resolves
  repeated text. Whitespace-only differences can be re-anchored.
- Unapplied export notes include the original passage and full proposed text.
  Insertions and export notices remain visible, as in the original workflow.
- Clause replacement does not silently truncate proposed language at 4,000
  characters. The quoted display snippet is not used as the deletion span.
- Contract analysis outputs and job completion commit together. Cancellation
  or loss of a worker lease cannot publish an orphaned saved analysis.
- Long drafting has a configurable one-hour default job budget, instead of the
  initial Go implementation's ten-minute cap. Section generation keeps the
  full plan and shared instructions, retries transient failures, and rejects
  reconciliation that drops or excessively shrinks sections.
- The original UI and Word add-in ship in the Go executable. The add-in uses
  token authentication without browser cookies; no additional UI server is
  required for the bundled deployment. Explicitly configured external pane
  origins support device/bearer tokens, without granting cookie credentials.
- Upload consumers wait for GoodMem's asynchronous indexing result before
  reporting a document indexed. The synchronous Python upload assumption is
  not carried into the new API client. Unit and real-browser tests cover this.

## Verification limits and remaining work

Passing fixtures proves only the tested cases. Live Microsoft SSO, connector
accounts, Word host editing, model semantic quality, every original upload
format/OCR path, and end-to-end UI parity are not yet verified. The bundled
artifact-runtime LibreOffice successfully rendered the new conversation export
samples and the two-page contract report/tracked-change variants; every Word/PDF
page was inspected. Other specialized export layouts still need acceptance.

Live connector-account verification and remaining document-format fidelity still
have implementation or integration work. Restored buttons are not evidence
that those workflows work. The route inventory stays pending until its full
contract is reviewed; it is not a feature-completion score.
